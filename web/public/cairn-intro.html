这是什么

// 定位 / What it is

Cairn 是一个可独立部署的容器镜像仓库:完整实现 CNCF Distribution(Docker Registry HTTP API V2), 自带管理控制台。它只有一个进程、一个二进制、一个 registry —— 起在哪儿,镜像就存在哪儿; 浏览器打开同一个端口,就是管理界面。

Cairn 用 Go 从零实现 —— 单二进制、自带控制台、零外部依赖（数据库 / 消息队列 / Redis 全不要）。 覆盖 docker push / pull / skopeo copy 的全 roundtrip,日常运维走 6 个内置页面 （镜像列表 / 拉取 / 热度 / 凭据 / 代理 / 设置）即可。

设计目标

// 四条硬约束 / Design goals
01
单进程单二进制
运行时不依赖数据库、消息队列、Redis 这类需要运维的外部服务;只依赖 Go 标准库 + chi + x/sync,最终二进制 ~10 MB。
02
前后端同源
React 前端构建产物经 //go:embed 打进二进制;同一个端口同时提供 /v2/*、/api/* 与页面 —— 没有跨域,也没有第二套部署。
03
库式后端
cmd/server 只做装配;能力都住在 internal/ 各包(registry / pull / stats / credentials / proxies / webhook),行为修改有唯一落点。
04
可观测
/healthz 存活、/readyz 就绪,日志走结构化 slog;compose 与 k8s 需要的探针端点开箱即用。

能力地图

// 已实现 / Capability map
/v2/*
镜像仓库协议
实现 catalog、tags/list、manifests(4 种 Accept 类型)、blobs 与 uploads(4 MiB 分块 PATCH / PUT);docker push / pull、skopeo copy、regsync(regclient)均已 roundtrip 验证(0.5.50 Range 头修复后 regsync 也通)。
repos/ · blobs/ · uploads/
本地存储
registry 内容落文件系统:digest 校验 + 原子写入;容器内固定 /app/data/registry,要让内容独占一块盘,加一条 bind mount 即可。
manifest
清单浏览与删除
按仓库 / tag 浏览 digest、架构、层数、体积与构建时间;删除按 digest 执行,执行前先列出同一 digest 的全部 tag 影响面。
queue
拉取队列
从上游 registry 拉取镜像:FIFO 队列、单并发执行、可协作式取消;进度用 ring buffer 限制内存占用。
AES-256-GCM
凭据与代理
凭据加密落盘(密钥来自 REGISTRY_CREDENTIAL_KEY),支持 Docker Hub / ghcr.io / quay.io 等的 Bearer 令牌流程(含无 scope token);代理库独立成表。
SQLite
热度库
SQLite(modernc 纯 Go 实现,无 cgo)记录拉取热度,按镜像与时间窗聚合;数据同样在 /app/data 下,备份数据目录即备份一切。
HMAC-SHA256
Webhook 通知
事件出站 POST 带 HMAC-SHA256 签名,接收端走白名单校验;接口响应统一 {success, code, message, data} 信封。
React · AntD
控制台
镜像列表 / 镜像拉取 / 镜像热度 / 凭据管理 / 代理管理 / 设置 —— 6 个页面覆盖日常运维。

单二进制架构

// 一个进程的四层 / Architecture
clients
docker / skopeo / curl 与浏览器 —— 全部指向同一个端口。
:8787
chi 路由 + slog 结构化日志;数据平面 /v2/*、管理平面 /api/*、Web UI(//go:embed)同源提供。
internal/
registry(协议与存储) · pull(拉取队列) · stats(热度) · credentials · proxies · webhook
/app/data
credentials.json · proxies.json · cairn.db · registry/(repos + blobs + uploads)
容器内监听端口是编译期常量 8787;对外端口由 compose 的 HOST_PORT 决定(默认 8787)。

快速开始

// 一条 compose 起服务 / Quick start
bash — 部署与探活 
# 数据目录:宿主机侧的数据落点(容器内固定 /app/data)
mkdir -p /data/cairn

# 生成配置(默认值即可跑)
cp .env.example .env

# 构建并启动
docker compose up -d --build

# 探活
curl -fsS http://localhost:8787/healthz
数据目录
HOST_DATA_DIR 默认 /data/cairn,挂进容器 /app/data;凭据、代理、热度库、registry 内容全在这里。容器重建不丢数据的前提是卷在。
配置分层
基础设施 env 只有 4 个:PORT、HOST_PORT、REGISTRY_CREDENTIAL_KEY、CAIRN_ENV;业务配置(仓库地址 / 代理 / 认证 / 保留天数)走设置页,保存即生效。
端口两层
容器内监听固定 8787(不可配);对外端口看 HOST_PORT。要挪数据只改宿主机侧的 HOST_DATA_DIR。

边界

// 刻意不做 / Out of scope

这些是明确的「不做」,而不是「还没做」:

✕登录 / 用户体系 / RBAC
✕镜像扫描 / CVE 检测
✕镜像签名 / cosign 集成
✕多 registry 聚合
✕配额 / 速率限制
✕Helm chart / OCI artifact 浏览
数据平面的鉴权
/v2/* 默认匿名可访问;设置页「Registry 认证」开 Basic auth(实时生效,无需重启),客户端 docker login 后才能 push/pull —— 0.5.3 加,0.5.33 修过 docker daemon 鉴权流程。生产部署仍建议放内网或反代之后,单层 Basic auth 不如多层稳。
